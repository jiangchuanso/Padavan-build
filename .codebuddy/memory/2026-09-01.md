## 修复 Padavan-build CI 工作流 bug（.github/workflows/build-padavan.yml）

克隆了 https://github.com/jiangchuanso/Padavan-build 并修复若干导致构建失败的 bug：

1. **`runs-on: ubuntu-20.04` → `ubuntu-22.04`**：GitHub 已于 2025-04-01 移除 ubuntu-20.04 托管 runner，旧值会让 job 直接失败。
2. **`actions/checkout@master` → `@v4`、`actions/upload-artifact@master` → `@v4`**：master 引用已不可靠/移除，pin 到稳定版本；upload-artifact 增加 `continue-on-error: true` 防止无产物时报错。
3. **`python-docutils` → `python3-docutils`**：Python2 包在 ubuntu-22.04 不存在；apt 列表新增 `ccache`（供 CONFIG_CCACHE=y 使用）。
4. **构建命令全部过时**：当前 `tsl0922/padavan`（main 分支）已删除 `toolchain-mipsel/dl_toolchain.sh`、`trunk/clear_tree`、`trunk/build_firmware_modify`。正确的官方构建方式是仓库根目录 `make <TARGET> TOOLCHAIN=mipsel-linux-musl`（Makefile 自动下载工具链并编译，产物在 `trunk/images/*.trx`）。
   - 改为：复制 `configs/templates/$TNAME.config` → `.config`，做 sed/echo 定制，再手动追加官方 `make $TNAME` 目标原本会注入的 `CONFIG_TOOLCHAIN=mipsel-linux-musl` / `CONFIG_CROSS_COMPILER_ROOT=/opt/rt-n56u/toolchain/toolchain-mipsel` / `CONFIG_CCACHE=y`，然后 `cd /opt/rt-n56u && make build TOOLCHAIN=mipsel-linux-musl`。
   - 验证：`CR660x.config` 在现有仓库 templates 中存在（默认机型有效）。
5. README 示例机型 `K2P` → `CR660x` 与默认一致。

注意：改构建机制依赖对 tsl0922/padavan Makefile 行为的推断（`make build` 会下载工具链并调用 trunk 编译）。未能在真实 CI 中实跑验证，建议用户先跑一次确认产物生成。

## 用户追加要求：源码改为 vb1980/Padavan-KVR

用户要求把克隆源从 `tsl0922/padavan` 改为 `https://github.com/vb1980/Padavan-KVR.git`。

关键差异（已核实）：
- vb1980/Padavan-KVR 是 **hanwckf 系 fork**：`trunk/` 下自带 `build_firmware_modify`(21KB)、`build_firmware`、`clear_tree`(438B)，以及 `toolchain-mipsel/dl_toolchain.sh`；**没有根目录 Makefile**，因此之前为 tsl0922 写的 `make build TOOLCHAIN=mipsel-linux-musl` 方案在此 fork 不适用。
- `build_firmware_modify` 约定：需 root（`sudo`），`$1`=板型名，`$2` 可选；当 `$2` 非空（如传 `0`）时**不会**用模板覆盖 `.config`，而是沿用工作流预先定制的 `.config`。所以原 hanwckf 模式 `cp ... .config` + sed/echo 定制 + `sudo ./build_firmware_modify $TNAME 0` 正确。
- `CR660x.config` 在该 fork 的 templates 中存在（7118 字节）。

最终方案：克隆 vb1980/Padavan-KVR → `cd toolchain-mipsel; sh dl_toolchain.sh` → `cd trunk` 做 .config 定制 → `sudo ./clear_tree; sudo ./build_firmware_modify $TNAME 0; sudo mv -f images/*.trx /opt/images/`。保留的现代化修复：ubuntu-22.04 / checkout@v4 / upload-artifact@v4(+continue-on-error) / python3-docutils / ccache。
